# Блог Кабана

Личный блог на русском языке: https://kaban.blog. Построен на Astro и Tailwind CSS, на основе [Astro Micro](https://github.com/trevortylerlee/astro-micro).

## Разработка

Node.js 24 LTS и npm (версия закреплена в `.nvmrc`, GitHub Actions и Netlify).

```sh
npm ci
npm run dev
npm run build
npm run preview
```

`npm run build` проверяет типы, собирает страницы, RSS, sitemap и поисковый индекс. GitHub Actions выполняет проверку при push в main и в pull request. Деплой Netlify настроен через `netlify.toml`.

## Как добавить запись

Создай `src/content/blog/название/index.md`:

```yaml
---
title: "Заголовок"
description: "Короткое описание для превью и поиска"
date: "2026-10-10"
draft: true
tags: [жизнь]
---
Текст записи.
```

`draft: true` скрывает запись из сайта, поиска, тегов и RSS. Поставь `false`, когда текст готов. Изображения можно хранить рядом с записью и ссылаться на них относительным путём. Для превью ссылки укажи `previewImage: /uploads/cover.jpg`, разместив файл в `public/uploads/`.

## Контент и настройки

- `src/content.config.ts` — единая схема всех коллекций.
- `src/content/books`, `games`, `movies`, `countries` — отзывы и города.
- `src/content/bookmarkItems/items.json` — закладки.
- `src/consts.ts` — название, описание и контакты. Пустой EMAIL скрывает почту.
- `astro.config.mjs` — публичный домен и интеграции.
- `public/admin/config.yml` — Decap CMS с входом через GitHub, отдельными черновиками и публикацией. Удалённый вход требует настроенного GitHub OAuth в Netlify; наличие файлов само по себе не подтверждает работоспособность входа.
- `archive/` — старые экспериментальные страницы; они не публикуются.

Для книг, игр и фильмов `rating` задаёт личную оценку от 1 до 5. Поле `draft: true` скрывает отзыв из подборки, сборки страниц и поиска. Название выводится из `title`; текст Markdown можно начинать сразу с впечатлений, а разделы оформлять заголовками `##`. Подборки сортируются по дате добавления, от новых к старым.

Демонстрационные проекты сохранены как черновики. Поисковый индекс генерируется при сборке и не хранится в Git. Изменения отправляются на GitHub вручную; сборка и локальное редактирование не выполняют push.

## Карточки ссылок

При сборке создаются JPEG 1200×630 в `/og/blog/<id>.jpg` для опубликованных записей и общая карточка `/og/site.jpg` для остальных страниц. Заголовок, вступление, нынешняя голова кабана и цвета блога собираются автоматически. Фотография выбирается в порядке: обложка `cover`, локальный `previewImage`, первая фотография Markdown. При `coverDisabled: true`, отсутствии или недоступности локальной фотографии получается текстовая карточка. Внешние изображения не скачиваются для карточек; внешние шрифтовые сервисы не используются. Кириллица и латиница рендерятся локальными PT Sans.

Страницы содержат абсолютные адреса картинок и метаданные [Open Graph](https://ogp.me/). Генератор [Satori](https://github.com/vercel/satori) и Sharp работают только во время сборки и не попадают в JavaScript читателя. После публикации карточка доступна мессенджерам; локальные ссылки `127.0.0.1` им недоступны, а ранее отправленные ссылки могут сохранять старое превью в кеше мессенджера.

## Зависимости

Сайт обновлён до Astro 7 и Tailwind CSS 4. На 10.10.2026 `npm audit` сообщает о нуле известных уязвимостей. Для `@tailwindcss/typography` закреплён исправленный `postcss-selector-parser` 7 через `overrides`; после обновления плагина это переопределение можно пересмотреть.

Tailwind 4 рассчитан на современные браузеры: Safari 16.4+, Chrome 111+, Firefox 128+. Поиск использует статический индекс Pagefind; сервер для поиска не требуется.

## Избранная запись и лента

Чтобы вывести запись крупно на главной, добавь `featured: true` в её frontmatter. Если таких записей несколько, будет выбрана самая свежая опубликованная. `excerpt` задаёт текст превью вручную; без него берётся первый фрагмент текста. Поле `cover: ./photo.jpg` ссылается на изображение рядом с постом, а `coverAlt` задаёт его описание. Обложка необязательна. Пример — `src/content/blog/italy/index.md`.

## Фотографии и связанные города

Фотографии в записях открываются крупно по нажатию. Перелистывание — кнопками или стрелками клавиатуры, закрытие — кнопкой, Esc или нажатием на фон. Без JavaScript фотографии остаются обычными изображениями в тексте. Изображения, которые уже служат ссылками, сохраняют свою ссылку.

Необязательное поле `cities: [rapallo, new-york]` в записи связывает её с городами. Используй имена файлов из `src/content/countries` без `.md`. В конце записи появятся ссылки на города, а на страницах этих городов — ссылки на рассказ. Черновики не показываются; неизвестный город вызовет ошибку сборки.

## Раздел «Мир»

Переключатель «По странам / По годам» меняет представление городов, не добавляя второй список на экран. Хронология использует только необязательное поле `visitedYear` («Год поездки», целое число от 1900 до 2100), которое доступно в редакторе города и CMS. Поле `date` остаётся датой карточки и не определяет год поездки. Города без `visitedYear` попадают в группу «Без года». После публикации карточки и пересборки города автоматически распределяются по годам; адрес `/world/#years` открывает хронологию сразу. Без JavaScript остаётся доступен обычный вид по странам.

Вверху показываются три города с фотографиями, от новых по дате поездки. Чтобы добавить снимок, укажи в файле города `photo: ../blog/italy/italy.jpg` и `photoAlt: Рапалло, Италия`; путь считается относительно файла города. Astro оптимизирует изображения и создаёт варианты для разных экранов. Поля есть и в CMS.

Каталог объединяет города и страны по алфавиту. Если город и страна названы одинаково, ссылка ведёт на страну с её списком городов. Боковая подборка использует `favorite: true`. Внизу появляются опубликованные записи с полем `cities` или тегами «мир», «путешествия», «поездки»; они сохраняют обычные превью.

Фотография из поля `photo` также показывается на странице города и открывается в просмотрщике. Под фотографиями в «Мире» даты выводятся без ведущего нуля и суффикса «г.». Поисковый индекс исключает служебную навигацию, оценки и даты; текст публикаций и названия мест остаются доступными для поиска.

Страницы записей и отзывов используют единую колонку для заголовка, текста, фотографий и блока после публикации. Её ширина задаётся переменной `--journal-reading-width` в `src/styles/global.css`; вложенные абзацы не имеют отдельных боковых отступов.

Страницы блога оформлены в духе Эгеи: крупный заголовок, компактная дата, текст Georgia и единая ширина снимков и абзацев. Используются собственные стили и PT Sans, без переноса шрифтов или кода исходного сайта. Внизу остаются темы, связанные записи и переходы; дата публикации также показывается в нижней полоске вместе с тегами.

Под записью расположена компактная полоска с датой и тегами. Блок «Дальше» выбирает до четырёх опубликованных постов с общими тегами: сначала больше совпадений, затем новые. Иллюстрация берётся из `cover`, `previewImage` или первого локального изображения в тексте. Если похожих записей нет, блок скрывается.

## Редактор блога

Админка находится по адресу `/admin/`. Редактор записей показывает текст и фотографии вместе с предпросмотром в стиле сайта. Фотографии новых записей сохраняются рядом с Markdown-файлом. Города выбираются из списка, а не вводятся вручную.

На опубликованном сайте **сохранение черновика** создаёт ветку и pull request в GitHub. **Публикация** объединяет изменения с `main` и запускает обычную сборку Netlify. Переключатель «Скрыть с сайта» — отдельное поле `draft`: оно исключает запись из публичных страниц даже после публикации её файла. Существующие тестовые записи не меняются.

### Вход на опубликованном сайте

1. В GitHub → Settings → Developer settings → OAuth Apps зарегистрировать приложение «Редактор kaban.blog», Homepage URL `https://kaban.blog`, Authorization callback URL `https://api.netlify.com/auth/done`.
2. В Netlify для этого сайта открыть Project configuration → Security → OAuth → Install provider → GitHub и добавить Client ID и Client Secret созданного приложения. Секрет остаётся в Netlify и не добавляется в репозиторий.
3. После отдельного пуша и деплоя открыть `https://kaban.blog/admin/` и войти через GitHub с аккаунтом, имеющим право записи в `Maligrond/kaban.blog`.
4. Проверить сохранение черновика и deploy preview перед первой реальной публикацией.

Инструкции: [GitHub backend Decap](https://decapcms.org/docs/github-backend/), [OAuth в Netlify](https://docs.netlify.com/manage/security/secure-access-to-sites/oauth-provider-tokens/).

### Локальная проба

В одном терминале запустить `npm run dev`, во втором — `npm run cms`, затем открыть `http://localhost:4321/admin/`. Локальный режим работает через Decap proxy и изменяет файлы на компьютере напрямую. Editorial workflow с ветками предназначен для удалённого GitHub backend; локальное сохранение не является пушем. Для проверки удалённой авторизации нужен опубликованный сайт с настройками OAuth.

## Режим автора внутри блога

Вход: `/author/` или незаметная ссылка 🐗 рядом с названием блога в футере. Логин и пароль вводятся только в стандартном окне GitHub; блог их не получает. В публичном меню ссылки нет. После подтверждения входа появляются «Новая запись», «Редактировать» (на странице записи), «Черновики» и «Выйти». Редактор открывается в основной области той же страницы. Резервная админка Decap остаётся на `/admin/`.

На опубликованном сайте проверяется GitHub-аккаунт `Maligrond` и его право записи в репозиторий. Пользователь GitHub без этих прав не получает авторские кнопки. Локальный режим доступен только на `localhost`/`127.0.0.1`, включается явно кнопкой «Попробовать локально» и требует `npm run cms`. Один лишь флаг в браузере не даёт прав записи в GitHub: все запросы проходят проверку GitHub API. Токен хранится в sessionStorage текущей вкладки и удаляется при выходе; в HTML и репозитории его нет.

Встроенный редактор сохраняет GitHub-черновики в ветках `codex/author/<адрес-записи>`. Публикация объединяет ветку с `main`, затем Netlify собирает сайт. Текст и фотографии отправляются одним коммитом. Это отдельный процесс от editorial workflow Decap: черновики встроенного редактора открываются его кнопкой «Черновики». Локально обе кнопки сохраняют файлы на компьютере; для черновика выставляется `draft: true`. Пуш выполняется отдельно.

Редактор использует Markdown с безопасным предпросмотром. Дата, теги и описание редактируются, остальные существующие поля (обложка, города, избранное) сохраняются. Адрес существующей записи менять нельзя. Сохранение проверяет версию файла и сообщает о конфликте вместо молчаливого перезаписывания чужих изменений. Провайдер GitHub OAuth уже установлен в Netlify; проверка через сервис авторизации завершилась ответом Authorized. Полный возврат из всплывающего окна в редактор и публикация на живом сайте ещё не проверены. При повторной настройке используй инструкцию выше.

Проверки API доступа и конфликтов: `node --test tests/author-api.test.mjs`.

### Автосохранение и фотографии

Несохранённый текст, поля записи и новые фотографии сохраняются в IndexedDB этого браузера. При повторном открытии редактора можно восстановить копию или удалить её. Если исходная запись успела измениться, редактор предупреждает об этом. После успешного сохранения в GitHub или локальный файл копия удаляется. Это восстановление на том же устройстве, а не синхронизация между устройствами; очистка данных сайта удалит копию. Токены входа в копию не записываются.

Фотографии можно выбрать кнопкой, перетащить в поле текста или вставить из буфера через ⌘V / Ctrl+V. Поддерживаются JPG, PNG, WebP и AVIF до 10 МБ на файл. Несколько перетащенных фотографий объединяются в галерею; кнопка «Галерея» делает то же при выборе файлов. Изображения отправляются в репозиторий только вместе с сохранением записи.

При добавлении фотографий открывается форма подписи и описания каждого снимка. Подпись необязательна. В Markdown она сохраняется в кавычках после адреса изображения. Несколько изображений на соседних строках без пустой строки между ними образуют галерею:

```markdown
![Описание первого снимка](photo-1.jpg "Подпись первого снимка")
![Описание второго снимка](photo-2.jpg "Подпись второго снимка")
```

Пустая строка между снимками оставляет их отдельными. Галереи выглядят как простая фотолента без кнопок и счётчика; листаются свайпом, горизонтальной прокруткой и стрелками клавиатуры после фокусировки; фотографии открываются в существующем просмотрщике. Без JavaScript фотографии остаются обычными изображениями в тексте.

### YouTube и оформление абзацев

В редакторе есть раскрывающаяся подсказка «Как оформить текст и добавить видео» с примерами и кнопками вставки.

Команда на отдельной строке перед абзацем меняет его оформление. После абзаца нужна пустая строка:

```markdown
.lead
Крупное вступление к записи.

.loud
Выделенная мысль.

.foot
Небольшое примечание.
```

Форматирование внутри абзаца (жирность, ссылки и т. п.) сохраняется. Это стили абзацев, а не нумерованные сноски.

Ссылка YouTube отдельным абзацем превращается в обложку с кнопкой воспроизведения. Поддерживаются обычные ссылки watch, youtu.be и Shorts. Плеер youtube-nocookie загружается только после нажатия; есть ссылка для открытия на YouTube. Ссылка внутри предложения остаётся обычной. Обложка загружается с серверов YouTube. Оформление и вставки работают в предпросмотре и в опубликованных записях.

Проверки URL видео: `node --test tests/post-enhancements.test.mjs`.

### Редактор и публикация

Основной экран редактора — заголовок и текст. Теги, дата, адрес и описание находятся в раскрывающихся «Тегах и настройках записи». Новый адрес строится по заголовку, пока его не изменят вручную. Пустое описание автоматически берётся из первого текстового абзаца; `descriptionAutomatic: true` сохраняет этот режим при повторном открытии. Явное описание имеет приоритет.

Предпросмотр показывает заголовок, текст, фотографии с подписями, дату и теги в оформлении записи. Фотографии можно увеличить, галереи листаются. Комментарии и рекомендации появятся на опубликованной странице.

Если GitHub сохранил черновик, но публикация не завершилась, редактор сохраняет актуальную версию и предлагает «Повторить публикацию». Повторная попытка публикует уже сохранённый коммит. Если после ошибки изменить текст, будет сохранена новая версия. Потерянный ответ GitHub проверяется по фактическому состоянию ветки; ошибка удаления служебной ветки не отменяет успешную публикацию.

Поиск показывает короткое описание и тип страницы. Команды `.lead`, `.loud`, `.foot` обрабатываются при статической сборке и не попадают в поисковый текст.

Архив доступен по `/archive/`, за год — `/archive/2025/`, за месяц — `/archive/2025/04/`. Ссылка находится в боковой колонке блога; заголовки годов также ведут в архив. Страницы создаются только для периодов с опубликованными записями, даты группируются по UTC так же, как отображаются в постах. Черновики исключены, списки архива не дублируют записи в поиске. Архив обновляется при обычной статической сборке.

Проверки: `node --test tests/*.test.mjs` и `npm run build`.

В авторском предпросмотре у Markdown-фотографий есть действия «Подпись» и «Удалить». Подпись и описание изменяются в форме, удаление можно сразу отменить. В галерее снимок перемещается за кнопку «Переставить»; стрелки рядом подходят для клавиатуры и телефона. Действия меняют исходный Markdown и сохраняются с записью. Посетители этих кнопок не видят. Удаление убирает снимок из текста, сохраняя уже опубликованный файл в репозитории; новые удалённые снимки не отправляются при сохранении.

На странице тега автор видит кнопку «Править тему». Введи новое название и нажми «Проверить изменения»: появится список затронутых записей, включая скрытые Markdown и MDX. Если название уже существует, темы объединяются, повтор целевого тега удаляется. Меняются поля `tags`, тело записи и остальные значения сохраняются. Локальное сохранение использует пакетный запрос Decap и не делает push. На опубликованном сайте отдельная кнопка «Сохранить и опубликовать» обновляет все файлы одним коммитом GitHub и запускает Netlify. Изменившаяся версия блога или отдельный черновик затронутой записи блокирует удалённое сохранение до повторной проверки либо завершения работы с черновиком. Старый тег исчезает, автоматическое перенаправление со старого адреса не создаётся.

### Карта поездок

В «Мире» карта раскрывается по ссылке «Карта поездок». Leaflet и подложка OpenStreetMap загружаются только после раскрытия; сервер и API-ключ не нужны. Колесо мыши прокручивает страницу, масштаб карты меняется кнопками. Выбрать город можно точкой на карте или списком; карточка показывает фотографию (если есть), личную оценку, начало впечатления и ссылки на город и связанные рассказы. Неопубликованные города и рассказы в карту не попадают.

Для нового города достаточно названия и страны: при статической сборке координаты автоматически находятся через [геокодинг Open-Meteo](https://open-meteo.com/en/docs/geocoding-api) (данные GeoNames). Читатель получает уже готовые точки, браузер не ищет координаты. Найденные значения кешируются в `node_modules/.cache/kaban-city-coordinates-v1.json`; изменение названия или страны запускает новый поиск. Кеш не является частью исходных записей, его удаление лишь повторяет поиск при сборке.

Поле «Координаты вручную — необязательно» в админке можно оставить пустым. Для уточнения места добавь `coordinates: [широта, долгота]`, например `coordinates: [44.3496, 9.22796]`; ручные координаты имеют приоритет. Это координаты города, а не маршрут или место проживания. При неоднозначном названии или недоступности сервиса сборка не ломается: город остаётся в списке, предупреждение выводится в журнал сборки, поиск повторяется при следующей сборке. В таком случае уточни название или заполни ручное поле. Черновики не отправляются на геокодинг.

Координаты существующих 59 городов взяты из [GeoNames cities1000](https://download.geonames.org/export/dump/) (11.10.2026, [CC BY 4.0](https://www.geonames.org/about.html)); одноимённые города сверены по стране и описанию записи. Подложка карты — © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright).


### Дополнительные блоки в записях

Все блоки работают на статическом сайте. Полный адрес отдельным абзацем, например `https://blogengine.ru/`, превращается при сборке в карточку с названием, описанием и обложкой. Ссылка внутри предложения остаётся обычной. Метаданные кешируются локально; недоступный источник не прерывает сборку. У новой ссылки в предпросмотре редактора сначала виден только домен.

Раскрывающиеся подробности (без JavaScript):

```markdown
:::details Подробнее

Обычный текст, **выделение**, ссылки и фотографии.

:::
```

Нумерованные сноски с возвратом к тексту:

```markdown
Текст с пояснением[^note].

[^note]: Само пояснение. Для следующих сносок используй другие имена.
```

Примеры доступны и в подсказке встроенного редактора. Страница `/now/` хранится в `src/content/pages/now/index.md` и редактируется через режим автора или коллекцию «Страницы» в Decap. Дата обновления задаётся автором в настройках. Ссылка на неё находится в «Обо мне».

### Предпросмотр и подборки в режиме автора

- «Посмотреть на сайте» в редакторе показывает текущий текст с оформлением записи, фотографиями, подписями, датой, тегами и похожими опубликованными постами. Сохранять или публиковать для этого не нужно. «К редактированию» возвращает к той же форме.
- «Править фотографии» включает действия с подписями и порядком снимков в предпросмотре.
- В разделах «Книги», «Игры» и «Мир» после входа автора доступны «Добавить книгу», «Добавить игру», «Добавить город». На странице существующей записи доступно редактирование.
- Подборки используют те же действия «Сохранить черновик» и «Опубликовать». После сохранения открывается предпросмотр результата. Публичные списки и карта обновляются после сборки; координаты нового города определяются по названию и стране.
- Вступление для ленты (`excerpt`) можно задать в настройках записи.

Перед публикацией редактор показывает итоговый адрес и проверяет обязательные поля и загрузку фотографий. Если фото не загрузилось, публикация недоступна до исправления файла или ссылки. Пустой текст — подсказка, а не запрет.

«Убрать в черновики» снимает существующую запись с публикации, сохраняя текст и фотографии. В GitHub сохраняется версия черновика в main, а сайт обновляется после сборки Netlify. Сохранённые правки из ветки черновика сохраняются вместе с записью; несохранённые поля редактора остаются в браузере. Обычная кнопка «Сохранить черновик» в GitHub оставляет опубликованную версию на сайте. В локальном режиме обе операции меняют только файлы на компьютере; пуш выполняется отдельно.

Фотографии, добавляемые в авторском редакторе через выбор файла, перетаскивание или вставку, обрабатываются в браузере перед сохранением. Длинная сторона уменьшается до 2560 пикселей без увеличения маленьких снимков; поворот учитывается при декодировании. Загружаемая копия заново кодируется из пикселей без EXIF, GPS и XMP, исходник на компьютере не меняется. JPEG сохраняется с качеством 90%, PNG — без потерь и с прозрачностью; WebP и AVIF преобразуются в WebP. Очень тяжёлый PNG может преобразоваться в WebP с сохранением прозрачности. Входной файл — до 40 МБ и 80 мегапикселей, подготовленный — до 10 МБ. Редактор показывает прогресс подготовки и сохранения фотографий, а рядом с подписью — размер до и после обработки. Уже добавленные раньше файлы не изменяются.

В редакторе поста блок «Обложка записи» открывает выбор из снимков в тексте и только что загруженных файлов. В предпросмотре включи «Править фотографии» и нажми под снимком «Сделать обложкой». Выбор, замена и удаление сохраняются вместе с записью, включая восстановление несохранённой копии в браузере. Обложка используется в ленте, похожих записях и превью ссылки после сборки; сама статья остаётся без дополнительного повторения обложки. «Убрать обложку» отключает также автоматическую подстановку первого снимка в похожие записи. Выбранный файл сохраняется, даже если он убран из текста.

Для города этот же выбор записывает главную фотографию и её описание в `photo` и `photoAlt`. Снимок появляется в «Мире» после сборки. Если он уже есть в тексте города, страница и предпросмотр показывают его один раз с исходной подписью. Все кнопки доступны только в авторском режиме; настройка не требует сервера.

Кнопка «Ссылка» в авторском редакторе открывает поиск опубликованных постов, городов, книг и игр. Выдели слова в тексте перед открытием окна — они сохранятся как текст ссылки. Без выделения подставляется название выбранной страницы; его можно изменить. Поиск учитывает название, теги поста, страну города, автора книги и год игры. В то же поле можно вставить полный внешний адрес с `https://` или `http://`. Ссылка вставляется в обычный Markdown, видна в предпросмотре и сохраняется вместе с черновиком. Список загружается только при открытии окна; в статическом индексе находятся только названия и адреса опубликованных страниц, без черновиков и текстов записей. После публикации новых страниц список обновляется при следующей сборке.

### Вариант оформления с полками

Главная показывает список последних записей по дате, без выделенной главной истории. Короткие записи выводят текст целиком, длинные — вступление и фотографию. «Мир» группирует города по странам; фотографии, даты, карта и ссылки берутся из существующих записей.

Обложки книг и игр лежат в `src/images/shelves/`, соответствия идентификаторам записей и источники — в `src/data/shelf-covers.json`. Изображения оптимизируются Astro при сборке и не требуют внешних запросов у читателя. Если обложки нет, полка показывает название на нейтральной плашке. Чтобы добавить обложку, поместите файл в эту папку и добавьте соответствие `books/идентификатор` или `games/идентификатор` в JSON. Картинка кабана — `public/android-chrome-192x192.png`.

Пометки для книг и игр выбираются в редакторе в поле «Пометка» и показываются на полке и странице произведения. Пустой выбор убирает пометку. Существующие записи остаются без пометок, пока автор сам их не выберет.

Для локального редактирования запускайте `npm run dev`: Astro следит за файлами и обновляет страницы после сохранения. `npm run preview` показывает только уже собранную папку `dist`; для обновления этого режима нужна повторная сборка. Локальная кнопка «Опубликовать» сохраняет файл и не отправляет изменения в GitHub.

Обложки книг и игр теперь можно загружать отдельно в редакторе или выбирать по прямой HTTPS-ссылке на изображение. Загрузка использует ту же подготовку фотографий: ограничение размера и удаление метаданных. Файл сохраняется вместе с записью; текст не меняется. Своя обложка заменяет стандартную из каталога, а «Убрать обложку» отключает её подстановку. В резервной админке также доступны поля обложки и ссылки.

На полках доступны «Обложки / Список»; предпочтение сохраняется в браузере. Фильтры появляются только для используемых пометок. Без JavaScript остаются все записи в виде обложек.

В просмотре фотографий можно увеличивать снимок двумя пальцами или двойным нажатием, перемещать увеличенное изображение и перелистывать обычные снимки горизонтальным свайпом. Кнопки, стрелки клавиатуры и Escape сохранены.

### Форматы записей и навигация

В редакторе блога доступен «Формат записи»: история, короткая запись, фотопост или ссылка с комментарием. Старые записи по умолчанию остаются историями. Короткая запись выводится в общей ленте целиком без заголовка; для поиска, RSS и адреса заголовок автоматически берётся из текста. Фотопост показывает первую фотографию с подписью. У ссылки заголовок ведёт на внешний сайт, а «Комментарий» — на страницу записи с обсуждением. Поля `format` и `linkURL` также доступны в резервной админке.

Поиск раскрывается под шапкой, открывается также из подвала и сочетаниями `/` или Ctrl/⌘K. Escape закрывает поиск. Результаты имеют ограниченную высоту, чтобы не занимать всю страницу.

При открытии записи из ленты ссылка «К списку записей» возвращает к этой записи в исходном разделе. Обычная история браузера сохраняет штатное поведение Astro. Для галерей соотношение сторон заранее берётся из размеров изображения, чтобы после загрузки фотографии не меняли ширину.
